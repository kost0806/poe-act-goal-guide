# PoE 액트 목표 가이드 오버레이

[![CI](https://github.com/kost0806/poe-act-goal-guide/actions/workflows/ci.yml/badge.svg)](https://github.com/kost0806/poe-act-goal-guide/actions/workflows/ci.yml) [![Release](https://github.com/kost0806/poe-act-goal-guide/actions/workflows/release.yml/badge.svg)](https://github.com/kost0806/poe-act-goal-guide/releases/latest)

Path of Exile 1 캠페인(1~10장)을 **최단 루트 순서대로** 게임 화면 위에 띄워 주고, 지역을 옮길 때마다 지금 할 일을 자동으로 짚어 주는 Windows 오버레이.

| | |
|---|---|
| 대상 게임 | Path of Exile **1** — 3.30 코븐스 오브 움브라 기준 (한국어 카카오 클라이언트) |
| 플랫폼 | Windows 10/11 · .NET 8 · WPF |
| 진행 감지 | 게임 로그 `Client.txt` / `KakaoClient.txt` 자동 감지 |
| 용도 | 개인용 로컬 빌드 |

## 가이드 내용

각 장의 루트를 **진행 순서대로 늘어놓은 단계 목록**이다 (전체 157단계). 단계마다 다섯 가지 꼬리표 중 하나가 붙는다.

| 꼬리표 | 내용 | 예 |
|---|---|---|
| **진행** | 장의 큰 줄기 — "~에서 ~ 처치" | 황혼의 해안: 힐록 처치 |
| **전직** | 미궁 도전(전직 시험) 위치와 미궁 시점 | 수용소 하층의 미궁 도전 · 지망자의 시험 (군주의 미궁) — 첫 전직 |
| **패시브** | 패시브 스킬 포인트를 주는 퀘스트 — "~에서 ~ 처치" | 물에 잠긴 심연: 심연의 주인 처치 |
| **작업대** | 작업대 옵션이 잠금 해제되는 지역 | 광산 1층: 작업대 '하얀색이 아닌 홈 최소 2~4개' ★ |
| **퀘스트** | 진행을 편하게 해 주는 퀘스트 | 도서관 → 문서 보관소: 황금 책자 4장 (시오사) |

★ 표시는 특히 중요한 단계(홈·이동 속도·저항 작업대, 미궁, 키타바의 저항 감소 등)다. 둘째 줄에는 가는 방향, 권장 레벨, 보상 NPC와 퀘스트 이름이 붙는다.

### 루트 출처와 3.30

- 순서는 공개 레벨링 루트 [exile-leveling](https://github.com/HeartofPhos/exile-leveling)의 최신 캠페인 루트(2026-07, 3.29용 갱신)를 따른다. 3.30 패치 노트의 캠페인 변경은 7·9장 리그 지역 등장, 6장 이후 아이템 등급, 미궁 끝 상자 제거 정도이고 퀘스트·지역 연결·보상 변경은 없어, 3.30에 가장 가까운 최단 루트로 판단했다.
- 루트 설정: **시즌 시작 루트**(미궁 도전 12개를 진행 중에 모두 깸) · **도적 모두 처치** · **도서관 포함**.
- 용어는 **한국어 클라이언트 표기**만 쓴다. 지역·보스·퀘스트·아이템·NPC 이름과 작업대 옵션 문구는 poedb 한국어판의 게임 데이터를 그대로 옮겼다 (예: 웨이포인트 → 거점, 소켓 → 홈, 전직 시험 지역 → ~의 미궁 도전, 일반 미궁 → 지망자의 시험).

## 화면

```
3장   7/23 단계                        장터 · 레벨 24
 [진행]   장터: 거점 활성화                          ← 지난 단계 (흐리게)
▌[전직]   지하 묘지의 미궁 도전                      ← 현재 단계 (강조)
          장터 입구 근처
 [작업대] 지하 묘지의 미궁 도전: 작업대 '공격 스킬의 원소 피해 증가'
 [진행]   전쟁터: 끈 감개 획득
          북쪽 거점 활성화 → 북서쪽
 ...
```

보기 방식은 세 가지다 (`Ctrl+Shift+C` 로 순환).

| 보기 | 보여 주는 것 |
|---|---|
| **기본** | 지난 단계 1개 + 현재 단계 + 앞으로 6개 |
| **간단히** | 현재 단계 + 다음 2개 (설명은 현재 단계만) |
| **액트 전체** | 그 장의 모든 단계 (지난 단계는 흐리게) |

## 진행 감지 방식

게임은 지역에 들어갈 때마다 로그에 `Generating level 2 area "1_1_2" ...` 줄을 남긴다. 이 지역 ID는 클라이언트 언어와 무관하므로 이것으로 현재 위치를 판단한다.

- **단계 이동**: 새 지역에 들어가면, 루트에서 4단계 안쪽에 그 지역이 있는 가장 가까운 단계로 넘어간다. 지나온 지역(마을 귀환, 이미 쓴 거점)으로는 뒤로 가지 않는다.
- **마을**은 수시로 드나들기 때문에 바로 다음 단계일 때만 넘어간다. 그래야 마을에 들를 때마다 다음 보고 단계로 건너뛰지 않는다.
- 한 지역에서 연달아 하는 단계(예: 서쪽 숲의 알리라 → 아테리)는 그 지역을 떠나 루트의 다음 지역에 들어가면 함께 완료 처리된다.
- **장 전환**: 루트가 다른 장의 지역을 가리키면(2장 중 1장 라이온아이 초소의 베스텔, 4·7·10장의 지망자의 광장, 8장 중 9장 하이게이트 거점) 지금 장을 유지한다. 그 외에는 지역이 속한 장으로 넘어간다.
- 황혼의 해안에 들어가면 새 캐릭터로 보고 모든 장의 진행을 처음으로 되돌린다.
- 시작할 때는 기존 로그 끝부분(최근 4MB)을 처음부터 다시 따라가 진행 위치를 복원한다.
- 자동 감지가 어긋나면 `Ctrl+Shift+←/→` 로 단계를 직접 옮길 수 있다.

로그 위치는 실행 중인 게임 프로세스 폴더 → 흔한 설치 경로(카카오/Daum, GGG, Steam) 순으로 `logs\KakaoClient.txt`, `logs\Client.txt` 를 찾는다. 못 찾으면 5초마다 다시 찾고, 트레이 메뉴에서 직접 지정할 수도 있다.

## 사용법

게임은 **창 모드 전체 화면(테두리 없는 창)** 으로 실행해야 한다. 전용 전체 화면에서는 어떤 오버레이도 보이지 않는다.

오버레이는 클릭을 받지 않는다(클릭이 전부 게임으로 통과). 조작은 단축키와 트레이 아이콘으로 한다.

| 기본 단축키 | 동작 |
|---|---|
| `Ctrl+Shift+G` | 오버레이 보이기/숨기기 |
| `Ctrl+Shift+→` / `←` | 다음 / 이전 단계 |
| `Ctrl+Shift+PageDown` / `PageUp` | 다음 / 이전 장 보기 (다음 지역 이동 시 자동으로 돌아옴) |
| `Ctrl+Shift+C` | 보기 방식 순환: 기본 → 간단히 → 액트 전체 |
| `Ctrl+Shift+M` | 위치 이동 모드 — 켜는 동안 마우스로 끌어 옮기고, 끄면 위치가 저장된다 |

트레이 아이콘(작업 표시줄 오른쪽)에는 위 기능과 함께 *로그 파일 지정*, *설정 파일 열기*, *가이드 데이터 폴더 열기*, *종료*가 있다.

### 설정

`%APPDATA%\PoeActGuide\settings.json` — 트레이 메뉴의 *설정 파일 열기*로 연다. 고친 뒤 앱을 다시 시작하면 적용된다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `clientLogPath` | `null` | 로그 파일 경로. 비우면 자동 감지 |
| `left`, `top`, `width` | 20, 160, 400 | 위치와 너비 (높이는 내용에 맞춤) |
| `backgroundOpacity` | 0.78 | 배경 불투명도 0.2~1 (글자는 항상 불투명) |
| `fontSize` | 13 | 글자 크기 |
| `viewMode` | `"Normal"` | `"Normal"`(기본) · `"Compact"`(간단히) · `"Full"`(액트 전체) |
| `hotkeys.*` | 위 표 | `"Ctrl+Alt+F5"` 형식. 빈 문자열이면 끔 |

## 빌드 · 실행

필요한 것: **.NET 8 SDK**, Windows.

```powershell
dotnet run --project src/PoeActGuide.App            # 실행
dotnet test                                          # 테스트 (Core만 대상, Linux에서도 실행 가능)
dotnet publish src/PoeActGuide.App -c Release -r win-x64 --self-contained false -o publish
```

`publish\PoeActGuide.exe`를 실행하면 된다. 가이드 데이터는 exe 옆 `Data\` 폴더에 복사되므로 다시 빌드하지 않고 고쳐 쓸 수 있다.

## 릴리즈

빌드할 필요 없이 [Releases](../../releases)에서 `PoeActGuide-vX.Y.Z-win-x64.zip` 을 받아 압축을 풀고 `PoeActGuide.exe` 를 실행하면 된다. .NET 런타임이 들어 있는 단일 exe(+ `Data\` 폴더)라 따로 설치할 것이 없다. 실행 중인 버전은 트레이 아이콘에 마우스를 올리면 보인다.

릴리즈는 GitHub Actions가 자동으로 만든다.

| 워크플로 | 언제 | 하는 일 |
|---|---|---|
| `CI` (`.github/workflows/ci.yml`) | `main` 으로 가는 PR 을 열거나 고칠 때 | **PR 제목 검사**, 빌드·테스트 |
| `Release` (`.github/workflows/release.yml`) | PR 이 `main` 에 **머지**될 때 | PR 제목으로 다음 버전 계산 → 테스트 → 단일 exe 게시 → zip 을 GitHub Release 로 게시 (태그 `vX.Y.Z` 생성) |

- 버전은 마지막 `vX.Y.Z` 태그에서 올린다. 태그가 없으면 `v0.0.0` 에서 시작한다.
- `main` 에 직접 푸시한 커밋은 릴리즈되지 않는다. 항상 PR 로 머지한다.
- 제목이 틀린 PR 이 머지되는 것을 막으려면 저장소 설정 → Branches → `main` 보호 규칙에서 **`PR 제목 검사`** 와 **`빌드 · 테스트`** 를 필수 상태 검사로 지정한다.

### PR 제목 규칙

PR 제목이 곧 버전 증가 종류와 릴리즈 노트 첫 줄이 된다. 형식은 [Conventional Commits](https://www.conventionalcommits.org/ko/) 를 따른다.

```
<종류>[(범위)][!]: <설명>
```

| 제목 | 버전 | 쓰는 경우 |
|---|---|---|
| `major: ...` 또는 종류 뒤에 `!` (예: `feat!: ...`) | **메이저** (1.4.2 → 2.0.0) | 이전 설정·데이터와 호환되지 않는 변경 |
| `feat: ...` | **마이너** (1.4.2 → 1.5.0) | 새 기능, 가이드에 새 내용 추가 |
| `fix:` `perf:` `refactor:` `data:` `docs:` `chore:` `ci:` `build:` `test:` `style:` | **패치** (1.4.2 → 1.4.3) | 버그 수정, 가이드 문구·지역 수정, 문서, 빌드 설정 등 |

- 종류는 영어 소문자, 콜론 뒤에 공백 한 칸, 설명은 한국어로 써도 된다.
- 범위는 선택이다. 가이드 수정이면 장 번호를 쓰면 찾기 쉽다.

예시:

```
feat: 다음 단계 단축키 추가                  → 마이너
feat(오버레이): 액트 전체 보기 추가           → 마이너
data(3장): 도서관 단계의 진입 지역 수정       → 패치
fix: 마을에서 단계가 건너뛰어지는 문제 수정    → 패치
docs: PR 제목 규칙 추가                       → 패치
feat!: 설정 파일 형식 변경                    → 메이저
major: 3.31 루트로 전면 교체                  → 메이저
```

규칙에 맞지 않는 예: `가이드 수정`(종류 없음), `Feat: ...`(대문자), `feat:설명`(공백 없음), `update: ...`(모르는 종류).

## 확인이 필요한 것

이 저장소의 코드는 Linux에서 컴파일과 Core 테스트, 그리고 exile-leveling 루트대로 1~10장을 지나가는 지역 순서 재생까지만 확인했다. **Windows에서 실제 게임과 함께 띄워 본 적은 아직 없다.** 처음 실행할 때 다음을 확인해야 한다.

- 카카오 클라이언트 로그 파일 이름이 `KakaoClient.txt`이고, 거기에도 `Generating level ... area "..."` 줄이 찍히는지
- 오버레이가 테두리 없는 창 모드 게임 위에 계속 떠 있는지, 클릭이 게임으로 통과하는지
- 기본 단축키가 게임 키 설정과 겹치지 않는지
- 실제 플레이에서 단계가 제때 넘어가는지 — 루트를 벗어난 동선에서는 `Ctrl+Shift+←/→` 로 맞춰야 할 수 있다

가이드 내용 중 아래는 확인하지 못했다.

- 3.30 전용으로 갱신된 공개 최단 루트는 아직 찾지 못했다(출시 3일째). 3.29 루트에서 달라진 점이 알려지면 반영해야 한다.
- 단계 설명의 방향·요령(예: "북동쪽", "물길을 따라가기")은 영문 루트 힌트를 옮긴 것이라 지역 생성에 따라 다를 수 있다.
- 미궁 도전 안의 작업대 옵션(예: 수용소 하층의 미궁 도전 → 이중 저항)은 1부와 2부 시험 이름이 같아, 어느 장인지는 exile-leveling 데이터를 따랐다.
